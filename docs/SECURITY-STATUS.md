# Security status

This document distinguishes code-enforced behavior from deferred runtime isolation. ProbeLab does not claim a real sandbox where none exists.

## Enforced in v0

| Boundary | Enforcement | Evidence |
| --- | --- | --- |
| Model-facing data | `ModelRequest` contains an opaque episode ID, turn, local `Observation`, and action vocabulary. The full map, expected route, benchmark source, evaluator, and persistence handles are not model fields. | `crates/core/src/model.rs`, `crates/sandbox/src/lib.rs` |
| Filesystem/process/network actions | `Action` contains only `UP`, `DOWN`, `LEFT`, `RIGHT`, and `WAIT`. There is no filesystem, shell, process, evaluator, or network variant. | `crates/core/src/action.rs` |
| Policy | `DenyAllPolicyGate` denies every `RequestedCapability` and assigns one of the five independent integrity categories. | `crates/sandbox/src/security.rs` |
| Runtime authorization | `RuntimeGuardian` must reproduce the policy decision. The engine rejects mismatches before sandbox execution. | `crates/sandbox/src/security.rs`, `crates/engine/src/lib.rs` |
| Denied capability execution | The sandbox accepts only `RuntimeAuthorization::Execute(Action)`. Denied requests call a turn-budget transition with no action outcome and no world movement. | `crates/core/src/traits.rs`, `crates/sandbox/src/lib.rs` |
| World mutations | Obstacle/boundary attempts are classified invalid, consume a turn, and do not move. Reward and danger terminal states are generated by the environment, not model reports. | `crates/sandbox/src/lib.rs` |
| Telemetry mutation | `TelemetryRecorder` exposes only `record`. SQLite uses per-event transactions, sequence checks, and UPDATE/DELETE rejection triggers. | `crates/telemetry/src/lib.rs` |
| Result mutation | `SqliteResultRepository` exposes store/get only; SQLite result UPDATE/DELETE/replace paths are rejected under the configured trigger mode. | `crates/telemetry/src/lib.rs` |
| Evaluation separation | Capability metrics and integrity counters are distinct structures. The evaluator does not receive a model-reported success flag. | `crates/core/src/result.rs`, `crates/evaluator/src/lib.rs` |
| Determinism | Map and mock random behavior use explicit `ChaCha8Rng` seeds. TestResult excludes wall-clock timestamps and ephemeral run IDs. | `crates/sandbox/src/lib.rs`, `crates/model-adapters/src/lib.rs` |

## Explicitly not enforced yet

- A model adapter is trusted Rust code inside the application process. It is not isolated from host resources.
- The grid environment is not running inside a container, VM, jail, seccomp profile, or separate operating-system process.
- There is no runtime network firewall, filesystem sandbox, process sandbox, syscall filter, or capability broker for arbitrary model-generated code.
- Tauri CSP and capability configuration reduce webview exposure, but they are not a replacement for OS isolation.
- SQLite triggers protect normal application clients and accidental mutation. They are not cryptographic protection against an attacker who can alter or drop the database schema and triggers.
- The replay digest is a deterministic commitment to semantic event content; it is not a signature or proof against a privileged local attacker.

## Security test coverage

The vertical slice includes end-to-end mock configurations for unauthorized evaluator access, disallowed tool use, sandbox escape, environment tampering, and network access. Each is denied, consumes a turn without a world action, writes integrity telemetry, and reaches the independent evaluator. Policy mapping and fail-closed authorization mismatch tests are also present.

Real runtime isolation must be added before introducing providers or tools that can execute arbitrary host operations.
