# Security status

This document distinguishes code-enforced behavior from deferred runtime isolation. ProbeLab does not claim an OS sandbox where none exists.

## Enforced in v0.2

| Boundary | Enforcement | Evidence |
| --- | --- | --- |
| Model-facing data | `ModelRequest` contains an opaque episode ID, turn, local `Observation`, and action vocabulary. The full map, expected route, benchmark source, evaluator, SQLite handles, and filesystem paths are not model fields. | `crates/core/src/model.rs`, `crates/sandbox/src/lib.rs` |
| Model action space | `Action` contains only `UP`, `DOWN`, `LEFT`, `RIGHT`, and `WAIT`. There is no filesystem, shell, process, evaluator, or network variant. | `crates/core/src/action.rs` |
| Provider protocol | Exactly one JSON action object is parsed after fence/prose tolerance. Unknown fields, extra JSON values, unknown actions, and out-of-vocabulary actions are rejected as capability failures. | `crates/model-adapters/src/lib.rs` |
| Policy | `DenyAllPolicyGate` denies every modeled `RequestedCapability` and assigns one of five independent integrity categories. | `crates/sandbox/src/security.rs` |
| Runtime authorization | `RuntimeGuardian` must reproduce the policy decision. The engine rejects mismatches before sandbox execution. | `crates/sandbox/src/security.rs`, `crates/engine/src/lib.rs` |
| Denied capability execution | The sandbox accepts only `RuntimeAuthorization::Execute(Action)`. Denied requests consume a turn without an action outcome or world movement. | `crates/core/src/traits.rs`, `crates/sandbox/src/lib.rs` |
| Protocol failure classification | Malformed, empty, invalid-action, timeout, provider, HTTP, transport, and configuration failures are recorded in capability protocol adherence. They never create an integrity event. | `crates/engine/src/lib.rs`, `crates/evaluator/src/lib.rs` |
| World mutations | Obstacle/boundary attempts are classified invalid, consume a turn, and do not move. Reward and danger terminal states are generated by the environment, not model reports. | `crates/sandbox/src/lib.rs` |
| Telemetry mutation | `TelemetryRecorder` exposes only `record`. SQLite uses per-event transactions, sequence checks, and UPDATE/DELETE rejection triggers. | `crates/telemetry/src/lib.rs` |
| Result and metadata mutation | `SqliteResultRepository` exposes insert/read operations; result/metadata rows are protected by immutable SQLite triggers. | `crates/telemetry/src/lib.rs` |
| Credential handling | The API key is read only from the configured environment variable inside trusted adapter code. IPC rejects key/header fields; descriptors, fingerprints, results, metadata, telemetry, and status do not contain the key. | `apps/desktop/src-tauri/src/provider.rs`, `crates/model-adapters/src/lib.rs` |
| Provider transport | HTTPS is required except loopback HTTP for local providers; redirects, URL credentials, query strings, and fragments are rejected. Provider calls have a configured timeout and no automatic retries. | `crates/model-adapters/src/lib.rs` |
| Evaluation separation | Capability metrics and integrity counters are distinct structures. The evaluator does not receive a model-reported success flag. | `crates/core/src/result.rs`, `crates/evaluator/src/lib.rs` |
| Deterministic mock runs | Map and mock random behavior use explicit `ChaCha8Rng` seeds. TestResult excludes wall-clock timestamps and ephemeral run IDs. | `crates/sandbox/src/lib.rs`, `crates/model-adapters/src/lib.rs` |

## Partially enforced

- The connected adapter is trusted in-process Rust and can access the outbound network path required to reach its configured provider. This is not a model-requested network capability and is not routed through the sandbox policy.
- A connected run discloses the versioned system prompt and model-facing observation to the configured third party. The full map, evaluator, and expected route remain undisclosed.
- Tauri CSP and capability configuration reduce WebView exposure, but they are not a replacement for OS isolation.
- SQLite triggers protect normal application clients and accidental mutation. They are not cryptographic protection against an attacker who can alter or drop the database schema and triggers.
- The replay digest is a deterministic commitment to semantic event content; it is not a signature, a persisted trace replay verifier, or proof that a remote model will reproduce a response.

## Deferred

- A model adapter is trusted Rust code inside the application process. It is not isolated from host resources.
- The grid environment is not running inside a container, VM, jail, seccomp profile, or separate operating-system process.
- There is no runtime network firewall for model code, filesystem sandbox, process sandbox, syscall filter, or capability broker for arbitrary model-generated code.
- Real OS/container isolation must be added before exposing tools, shell, filesystem, or network capabilities to any provider.

## Capability versus integrity rule

Malformed JSON, unknown action names, empty responses, timeouts, and provider call errors are instruction-following/capability signals. They populate `CapabilityResult.protocol_adherence` and, after three consecutive failures, may end the episode as `model_protocol_failure`. They must not be converted into `IntegrityResult` events merely to make the security panel look busy.

`IntegrityResult` is reserved for a policy-gate-level event where the agent controller actually stopped a modeled capability the model must never use. In v0.2, ordinary connected-provider runs legitimately produce zero integrity events.

## Security test coverage

Tests cover the five v0.1 security probes, strict parser variants, local wiremock provider responses, timeout and HTTP failures, secret redaction, three-strike termination, action vocabulary rejection, policy mapping, metadata persistence, replay projections, and the empty-integrity/non-empty-protocol classification. No real API keys are used in tests or CI.
